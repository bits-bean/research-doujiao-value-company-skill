# 商业模式中的具体对象与价值交换

研究“价值如何创造、传递与回收”时读取本文件。图中的对象、名称、数量、插图语义和连接关系都来自当前公司的生意，不能先画通用四角模板再填公司名。

## 取证与命名

- 依据已实际打开的官方业务介绍、销售模式、合同收入、采购及合作安排，识别使用者、实际付款方、产品或服务的交付方、销售渠道和必要的供给方。只纳入解释主要价值交换所需的对象，不按固定数量凑齐角色。
- 图上直接使用具体身份或产品名称。不能把“客户”“产品与渠道”“生态伙伴”“公司”等分类标题当作最终对象名；公司节点使用当前公司名称。相同公司可以有多类使用者与付款方，同一人也可能以不同交易身份参与，须说明区分依据。
- 免费使用者不自动等于付款客户；广告主、平台商户与消费者的款项分别指向真实收款方。经销商收取的零售款不能画成上市公司直接收入；合作分成、采购支出不能画成收入。合作关系也不证明必然有数据回流。
- 每条连线写清“谁向谁提供什么 / 支付什么”，分别使用资金、价值或数据语义。仅在来源确实支持时画数据反馈。不为闭环造型补造关系，不用收入分部名称推断完整交易网络。
- 每个对象和每条关系都绑定同一研究包中的 `source_ids`；证据台账或报告保存业务段落的精确来源定位。经营事实与研究概括分开，未披露的交易机制留作明确限制，不让网站自行研究或补写。

## 冻结交接

在 `evidence-ledger.json.business_model` 保存专用图谱，随证据台账进入同一 v2 冻结清单。对象与关系的精确来源定位可保存在同台账的 `business_model_source_review`，逐项指回对象 / 关系 ID、来源 ID 与原件段落。不扩展锁定的 `company.json` Schema，不把图谱塞进收入 `segments`、行业指标或计算金额字段。

| 字段 | 契约 |
|---|---|
| `version` | 固定 `"1.0"` |
| `period` | 与 `company.json.income_statement_sankey.fiscal_year` 相同的完整财年 |
| `company_identity` | `company_name_en / ticker / exchange` 与该包 `meta` 精确一致 |
| `actors[]` | `id / label / label_en / detail / detail_en / illustration / source_ids` |
| `flows[]` | `id / source / target / label / label_en / kind / source_ids` |
| `notes / notes_en` | 字符串，说明业务范围、概括方式、交易身份重叠或未覆盖的次要业务；箭头不是精确会计流量 |

对象及连线 ID 使用小写字母开头、小写字母 / 数字 / 连字符组成的最多 64 字符，分别唯一。恰好一个对象使用 `id: "company"` 和 `illustration: "company"`；其他对象 ID 由实际语义命名。每条关系的起终点必须存在且不同，每个对象至少参与一条关系；整图与公司节点连通。`kind` 只用 `money / value / data`，每个 `source_ids` 为非空、不重复的有效来源 ID 数组。

`label` 是简洁中文图上名称，`detail` 补充该对象在当前生意中的身份或作用；英文对应字段表达相同意思。对象数量可随公司变化，不能把不同付款机制的身份合成一个空泛标签以迁就布局。

`illustration` 表达对象的可视语义，使用当前下游图例库的键：`company / cardholder / merchant / travel / gamer / advertiser / cloud / creator / distributor / consumer / supplier / search-user / developer / bank / social-user / digital-buyer / search-distribution`。研究层选择与实际角色相符的语义，实际 SVG、来源许可与布局由网站或内容层管理；同一种真实角色可以复用同一图例，不能按“左上 / 右上 / 右下”位置固定套用三张图。需要新类型时先明确具体语义并更新下游图例契约，不借用含义不符的插图。

报告商业模式章节用通俗文字解释主要对象与交易关系，机器字段和图例键只留在证据台账与完整度说明。图谱新增事实执行相应来源复核；仅把已审阅事实组织成图谱时，记录对应段落、来源和关系方向的复核，不改写财务、估值或投资判断。

## 验证与网页消费

新完整研究、修复或增量交接须提供此图谱。历史包缺少该字段只可作兼容审查，不能声称已经具备个性化图谱。验证器检查身份、期间、来源解析、具体命名、唯一 ID、连接引用、连通性与图例语义键；经济关系和来源是否真正支持标签仍需语义复核，结构通过不等于事实正确。

网站与导出器从同一版本的证据台账读取对象和连线，按具体 `illustration` 配置有来源和许可的图例；公司节点使用已验证公司标识。布局根据实际对象数量和连接方向安排，名称在宽窄屏均应清晰可读。已有有效图谱时不得回落到通用角色或按行业、股票代码猜测对象；身份错配、来源缺失或连接无效时应明确显示数据缺口。

验收需比较不同生意、不同对象数量、免费使用者与付款方分离、直接与间接销售关系，逐条核对图上的名称、插图、箭头方向和来源。名称或图例没有变，而仅替换了公司标识，不算完成跨公司适配。
