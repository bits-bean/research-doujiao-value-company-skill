# 估值与 Reverse DCF 质检

## 读者先看到什么

估值部分先解释方法，再展示公式。首次出现时使用：

- 现金流折现（DCF：把未来每年的可分配现金换算成估值日价值）；
- 反向现金流折现（Reverse DCF：从当前股价反推市场已经计入的经营要求）。

不要让读者从最终每股价值倒猜中间过程。正文按“现金流从哪里来 → 每年如何变化 → 怎样折现 → 终值怎样算 → 总额怎样变成每股价值”的顺序写。

## 估值快照与现金流口径

记录估值日、股价时间戳、交易所、币种、稀释后股数、现金、总债务、净债务、市值和企业价值。市场价格和汇率必须有估值日可追溯来源。先研究企业质量和风险，再估值；不得为了得到预期结论反向调整参数。

DCF 不是“给每股收益乘一个倍数”。先按企业类型选择真正可分配的现金：

- 普通企业：企业自由现金流（FCFF：可供债权人和股东共同分配的现金）、股权自由现金流（FCFE：偿还债权人并满足再投资后可供普通股股东分配的现金）或所有者收益（Owner Earnings：维持企业竞争力后可供股东支配的现金）；
- 银行、保险及其他受监管金融企业：正常化普通股净利润减去维持目标监管资本和支持业务增长所需的普通股留存，得到可分配普通股现金；
- 无法可靠建立现金流口径时，降低置信度或归入 Too Hard，不得用 EPS 填补。

正式报告和计算台账共用同一个估值起点，并写清现金流口径、基准期间、估值基准日现金总额、稀释后股数、基准日每股现金、预测年限、折现率、永续增长率和终值依赖。总额折现后才除以稀释后股数；EPS、PE、P/TBV 和退出倍数只作交叉验证。

计算台账使用实际原始数值，不使用千、百万或十亿缩放：人民币1,868亿元写 `186800000000`，91.53亿股写 `9153000000`。中文报告再换算为亿元 / 万亿元、亿股和原币种/股，验证器把展示值还原后与台账核对。

## 模型适用性门

建模前先说明要估的是企业整体现金权利还是普通股股东现金权利，并检查资本约束、杠杆、周期性、少数股东、分部差异和现金是否真的可分配。模型适用性审查集中写入 `evidence-ledger.json.valuation_review.model_applicability`，机器字段执行 [research-execution-and-audit.md](research-execution-and-audit.md)，至少记录：

- 主 DCF、Reverse DCF 和至少一种交叉验证分别解决什么问题；
- 每个模型是 `appropriate / limited / inappropriate`，以及适用或受限理由；
- 关键假设、结果方向与支持主张；主模型通过 `role: primary` 明确，不以数值高低选择。

模型能算出数值不等于适用。普通企业可在 FCFF、FCFE 与 Owner Earnings 中选择；银行、保险等受资本约束企业优先使用可分配普通股现金或有经济依据的剩余收益；资源周期、REIT 和分部差异显著企业使用相应行业适配模型。无法说明现金权利和资本约束时停止 DCF，不得用固定折现率区间、统一终值公式、EPS 或退出倍数补洞。

## 假设必须对应明确年度

所有显性期假设都绑定预测年度。使用“第1—5年增长8%，第6—10年增长6%”，不要只写“初期8%、后期6%”。若确需使用“第一阶段”等辅助名称，名称旁必须同时出现完整起止年度。

以下词不能脱离明确年度范围充当估值参数：初期、前期、中期、后期、早期、第一阶段、第二阶段、长期增长。“永续增长”专指显性预测期结束后的终值假设，不等同于含糊的“长期增长”。自然年度模型还应同时标注对应日历年，例如“第1年（FY2027）”。

每个阶段同时说明经济驱动，不只给一个百分比：

- 普通企业：收入、利润率、税率、折旧摊销、资本开支和营运资金怎样形成 FCFF / FCFE / Owner Earnings；
- 受资本约束金融企业：普通股利润、风险加权资产（RWA：用于衡量银行承担风险规模的监管口径）、普通股一级资本充足率（CET1：核心普通股资本占 RWA 的比例）、必要留存和可分配普通股现金怎样逐年衔接。

若结构化字段只能表达一个增速，而模型同时预测收入与利润，报告直接披露两者各自的经济假设及准确年度；字段映射和兼容原因放在 `schema-gap-report.md`，不进入投资者正文。

## 报告中的完整计算链

非 Too Hard 的正式报告至少包含以下六组内容，三情景均不可省略：

1. **基准日现金桥接**：现金流口径、基准期间、现金总额、稀释后股数、每股现金和预测年限；金融企业另展示正常化普通股利润减必要留存，普通企业展示选择该现金流口径的计算。
2. **分阶段假设表**：每个情景的准确年度范围、经营驱动、折现率和永续增长率；多阶段必须逐段列出。
3. **逐年折现表**：情景、预测年度、经营驱动、可分配现金、折现因子、当年现金流现值。每个情景完整覆盖第1年到预测期最后一年。
4. **终值桥接**：最后一年现金、永续增长率、折现率、终值、末年折现因子和终值现值，并展示公式 `终值 = 最后一年现金 × (1 + 永续增长率) ÷ (折现率 − 永续增长率)`。
5. **股权价值桥接**：显性期现金流现值合计 + 终值现值 = 股权价值；股权价值 ÷ 稀释后股数 = 每股价值。若使用 FCFF，还必须展示从企业价值到股权价值的净债务等调整。
6. **敏感性与 Reverse DCF**：敏感性矩阵围绕基准情景；Reverse DCF 说明现价隐含的至少两个经营维度、现实比较和推翻阈值。

表格可按情景拆开以保持可读，但不得把逐年数字藏到仅机器可读文件。正文可以四舍五入，所有合计必须在展示精度内相加成立，并能反向核对计算台账。

## 计算台账的逐年记录

`calculation-ledger.json` 用三类 `valuation_role` 保存与正文相同的链条：

- `annual_discounted_cash_flow`：每情景每预测年度一条，`result = cash_flow * discount_factor`；
- `terminal_present_value`：每情景一条，以最后一年现金、永续增长率、折现率和末年折现因子复算终值现值；
- `equity_value_bridge`：每情景一条，以显性期现值和终值现值得到股权价值，并复核稀释后每股价值。

三个情景使用 `bear / base / bull`，年度必须连续、无重复并完整覆盖 `1..forecast_years`。计算台账保留未缩放原始数值和足以复算现金流的业务驱动；报告只换算展示单位，不改变数字含义。

FCFF 的 `equity_value_bridge` 保留 `explicit_period_present_value + terminal_present_value - net_debt` 的原定义。明确识别的额外桥项可使用：加回 `nonoperating_securities`（非经营证券）和 `nonoperating_assets`（除证券之外的其他非经营资产），扣减 `minority_interests`（少数股东权益）和 `preferred_equity`（优先股权益）。这些输入必须为非负金额，在三情景正文价值桥分别列出与台账同名语义的金额列，并由实际公式、股权价值与每股价值相互核对；不能通过改写净债务定义、把桥项藏入现值或只写一段说明通过验证。除上述受控输入外的额外项先解决契约，不静默忽略。资产项目不得重复计量，是否可分配及其估值应由来源和模型适用性说明支持。

Reverse DCF 的字段和表格维度按所反推的经济指标归类。`base_revenue_path_required_operating_margin` 等字段反推的是利润率，路径中的 revenue/growth 仅描述条件，不能据此误归为增长维度。至少两个经营维度及现实比较、推翻阈值的要求不变；利润率数值必须与对应台账/结构化值一致。

## 风险只归位一次

在 `evidence-ledger.json.valuation_review.risk_placements` 中为每项重大风险记录风险标识、经济传导、唯一归位、受影响情景、对应主张和防重复理由；具体机器字段执行 [research-execution-and-audit.md](research-execution-and-audit.md)。唯一归位只使用：

- `cash_flow`：进入收入、利润率、资本开支、营运资金、信用损失、必要留存等经营输入；
- `scenario`：只在一个或多个完整情景中表达；
- `tail_case`：低频但足以破坏持续经营或现金权利的离散事件；
- `discount_rate`：无法在现金流中表达且确属系统性的风险。

同一风险只能选择一个归位。公司特有且可观察的风险优先放入现金流、情景或尾部事件，不得同时下调增长、提高折现率、再额外扩大安全边际。每项 `rationale` 必须说明已检查哪些参数和情景；只写“无重复”不算完成。安全边际用于处理估计误差和结论韧性，不是再次扣罚已经建模的同一风险。

## 硬约束与判断

- 终值增长率必须低于折现率；
- 悲观价值 ≤ 基准价值 ≤ 乐观价值；
- 敏感性表必须围绕基准假设，不得只展示有利格子；
- 现金流口径、折现率和价值口径必须匹配；
- 稀释后股数必须包含可预见稀释；
- EPS、PE 或退出倍数不得作为 DCF 起点或 Reverse DCF 目标变量；
- 关键假设必须能追溯到历史基线、行业事实或明确分析假设；
- 逐年现值之和、终值现值、股权价值和每股价值必须机械复算一致。

任何阈值、参数带宽和情景跨度都必须来自公司历史、行业经济、监管约束或明确的外部基准。不得跨币种、跨行业硬编码统一折现率、增长率、终值占比、Beta 或安全边际；`EPS × 目标 PE` 只能是倍数交叉验证，不能命名为 DCF、三情景现金流估值或内在价值主模型。

结果主要依赖遥远终值、多个低确定性变量，或很小参数变化就翻转时，降低置信度并扩大价值区间；必要时归入 Too Hard。

## 3×3 结论稳定性

每个非 Too Hard 的基准模型必须给出九格敏感性，并在 `evidence-ledger.json.valuation_review.conclusion_stability` 保存与 `company.json.valuation.dcf_sensitivity` 完全相同的九组折现率、永续增长率及其估值状态，以及结论是否实质翻转和处理动作；具体机器字段执行 [research-execution-and-audit.md](research-execution-and-audit.md)。当前 Schema 的九格固定使用折现率与永续增长率；若利润率、留存资本或周期中枢价格更关键，把它们作为补充敏感性写入报告和计算台账，不得改义这九格。

每个 `cells[]` 项保存折现率、永续增长率和按统一规则映射的估值状态。九格不能只展示价值数字；必须检查相邻合理格子是否使结论在低估、接近合理和偏高之间发生实质翻转。`verdict_flip: true` 时，`action` 必须选择 `downgrade / too_hard`，降低估值置信度、扩大区间并说明哪一项证据可缩小不确定性。参数步长不使用固定百分点，按企业和行业事实确定。

## 多模型冲突解释

DCF、Reverse DCF、分部估值、剩余收益、资产价值、周期中枢或倍数交叉验证不要求得出相同数字，但必须解释差异。冲突解释集中写入 `evidence-ledger.json.valuation_review.model_conflicts`，具体机器字段执行 [research-execution-and-audit.md](research-execution-and-audit.md)，至少包含：

- 冲突模型、冲突方向与适用边界；
- 权威价值依据、解释和对最终结论的影响；
- `status: resolved / unresolved`；未解决且会改变估值状态时不得冻结。

不得把冲突结果机械平均、反向调参强迫收敛、用“保守”一词跳过解释，或只保留支持预期结论的模型。交叉验证只能检验主模型是否异常，不能替代现金流权利分析。若无法解释的冲突足以改变估值状态，必须降低置信度、列入尚待调查问题，必要时归入 Too Hard。

## Reverse DCF 与情景回报

从估值日市场价格反推市场隐含的可分配现金增长，以及利润率、资本强度、留存率或现金回报中的至少另一个维度。不要只输出一个增长率，更不得只反推 EPS。说明市场隐含什么经营组合、与历史和行业现实相比是否合理、哪些变量最敏感，以及什么结果会使当前价格显得过高或过低。

在一致的持有期、分红、回购/稀释和退出估值假设下计算悲观、基准、乐观年化回报。情景名称保持同一维度。

银行和保险不得机械使用普通企业无杠杆 FCF DCF；股息、回购、账面价值、剩余收益和 P/TBV 只作交叉验证。资源与强周期公司使用周期中枢价格和成本，REIT 使用 AFFO/NAV 与债务结构，高 SBC 软件公司把真实稀释纳入每股价值。

### 下游稳定字段与适用性

研究层先决定指标是否适用，再把可复算结果写入 `company.json.valuation` 和 `calculation-ledger.json`。下游不得靠猜测字段名、从报告散文提数，或把不适用项目渲染成空卡片。适用但缺证据的值保持 `null` 并写入完整度说明；不适用项目不进入该分类的展示清单。

受监管银行与 `payments_credit` 优先使用下列稳定键；只写有来源且已入计算台账的项目：

- `multiples.pe_ttm_common_earnings`、`multiples.ttm_common_earnings_yield`；
- `multiples.price_to_total_book_value`，并用说明明确它不是 P/TBV；只有普通股有形权益分母完整时才另写有形账面倍数；
- `multiples.ttm_common_earnings_per_diluted_share`、`multiples.price_to_owner_earnings`、`multiples.owner_earnings_yield`；
- 按同一 TTM 期间与估值日市值计算的 `multiples.ttm_cash_dividend_yield`、`multiples.ttm_buyback_yield`、`multiples.ttm_shareholder_distribution_yield`，并明确它们是历史分配强度，不是未来回报承诺；
- `reverse_dcf.implied_distributable_cash_cagr`、`implied_starting_distributable_cash`、`implied_starting_payout_ratio`、`implied_regulatory_capital_retention_ratio`，以及至少一个资本约束维度，例如 `implied_rwa_growth_at_target_cet1`；
- `reverse_dcf.comparison_to_history` 与 `sensitivity_and_threshold`；
- 每个 `expected_returns[]` 保留 `horizon_years`、`scenario`、`annualized_return` 与 `assumptions`，并在计算台账保存同一现金流和终值路径反解的年化回报。

不得为填满界面补造 Forward P/E、P/TBV、EV/EBIT、普通企业 FCF Yield，或把“剔除投资资产后增长”等普通企业指标套给受监管支付信贷公司。新增生产者必须使用上述稳定键；下游可读取历史别名作兼容，但不得让历史别名继续成为新包的事实标准。

安全边际与业务稳定性、资产负债表、治理、数据质量和估值不确定性匹配。估值结论与企业质量、研究状态分开表达，并保留最强反证和 thesis breakers。
