# 维护研究 Skill

仅用于用户要求阅读、优化或修复本 Skill 的任务，不启动公司研究、能力来源探针或公司包冻结。

## 选择基线

1. 核对源码仓库、当前分支与工作区、最新 `origin/main`（可访问时）及用户指定的安装目录；比较完整文件清单和 SHA-256，不以 commit 相同代替文件相同。
2. 源码旧于安装目录时，先找到安装版本对应的基线；有用户改动时保留或隔离处理，不能用旧源码覆盖新安装。使用新分支或必要的隔离工作区，保留无关文件。
3. 根据真实矛盾或复现结果优化。入口保留任务分流、共享硬约束与引用入口；专项细节集中在现有 reference，不为缩短入口删除研究或交付要求。

## 锁与边界

- 本任务的维护授权允许修改 Skill 指令、执行脚本和测试，并刷新相应 `execution_integrity`；它不授权修改公司研究数据、上游 Schema、历史冻结包或远端写入。
- 三份兼容协议及 `research_protocol` 元组保持原样。Schema 副本和 `company_schema` 保持原样；若需协议 / Schema 迁移，应作为单独的明确变更处理，不能顺手改锁让验证通过。
- 修改规范或脚本后，依据 `scripts/validate_skill.py::expected_execution_artifacts()` 的实际清单，按 `path` 排序重算每个 artifact 的 `sha256 / size_bytes`，保留正确 `role`；用同文件的 `canonical_sha256()` 分别计算 normative、toolchain 与完整数组的聚合摘要。
- 只刷新 `execution_integrity` 的 artifacts 和三个摘要；`source_binding` 保持真实的 `unverified`，不编造远端来源 commit。生成后用原锁对比，确认兼容协议与 Schema 块完全不变。
- 更新后的执行摘要会改变新研究的运行指纹；旧冻结包不原地重签。说明这是本地 Skill 版本，不能声称已经远端发布。

## 验证与安装

从源码根目录执行：

```bash
python3 scripts/validate_skill.py
```

该命令包括包结构 / 链接 / 完整性检查、脚本编译、自测和完整 unittest discovery；成功后无需再原样跑一遍全套测试。对实际修改的逻辑补有意义的回归场景，不用测试强行锁死行文。复杂指令改动再用独立上下文做有限情景检查，例如只审查旧包、增量冻结、配色受阻与已获授权的第三方 Logo。

通过后同步到用户指定的本地安装目录：先保留可恢复备份，再同步完整受管文件；保留 `.DS_Store` 等无关文件，不把 `.git`、缓存或临时测试产物当作 Skill 内容。验证安装文件清单与源码逐文件 SHA-256 一致，确认 Skill 可发现。安装前后若出现并发变更，重新核对差异，不能盲目覆盖。

最终交代优化点、验证结果、安装路径与是否已远端提交；完整性相等、测试通过、模型发现和远端发布是不同事实。
